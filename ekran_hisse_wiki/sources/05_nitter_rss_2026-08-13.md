# Oturum 2026-08-13 (2) — Twitter/X → Nitter RSS köprüsü

## Bağlam
Önceki oturumda X API v2 `search/recent` endpoint'inin **HTTP 402 "credits
depleted"** döndürdüğü teşhis edilmişti (hesap kredisi tükendi; kod değil hesap
sorunu). Kullanıcı **ücretsiz** çözüm istedi ve iki tercih yaptı:
- Kaynak modeli: **anahtar-kelime araması (Nitter search RSS)**.
- Instance: **yapılandırılabilir + çoklu fallback**.

## Yapılan kod değişikliği
`twitter_client.py`'nin **içi** Nitter search RSS'e çevrildi; public API
(`fetch_recent`/`fetch_ids` + `(tweets, users, err)` / `(ids, err)` callback
şekli) **birebir korundu** → `overlay.py`, `logic.py` ve overlay testleri
değişmeden çalışıyor. Bearer token artık kullanılmıyor.

Yeni iç yapı:
- `_DEFAULT_INSTANCES` — kod içi fallback listesi (nitter.net, privacydev,
  poast, xcancel).
- `_instances()` — `config.NITTER_INSTANCES` (virgülle çoklu) doluysa onu, yoksa
  varsayılanı.
- `_clean_query(query)` — X-özel operatörleri (`lang:`, `-is:retweet`, `filter:`)
  regex ile sıyırır; parantez/`OR`/sembolleri bırakır; boş kalırsa orijinali
  kullanır.
- `_fetch_rss(query)` — her instance sırayla `GET {inst}/search/rss?f=tweets&q=...`
  (timeout 10); 429'da Retry-After/backoff (`_MAX_RETRIES=2`, `_MAX_BACKOFF=30`),
  sonra sıradaki instance. Baştaki boşluk `body.lstrip()` ile kırpılır (bazı
  instance'lar XML öncesi boşluk ekliyor). Tümü düşerse `(None, "kaynak yok")`.
- `_parse_item(item)` — `<link>`/`<guid>`'den `/status/(\d+)` id; `<title>` →
  `html.unescape` metin; `<pubDate>` (RFC822) → `parsedate_to_datetime().isoformat()`
  (overlay `tw_ago` ISO bekliyor); `author_id = username` (Nitter'da numeric id
  yok); `<dc:creator>` → `@handle`.

`config.py`: `NITTER_INSTANCES = get("NITTER_INSTANCES")` eklendi (sır DEĞİL,
public URL). `overlay._twitter_token()` → `return True` (kaynak her zaman denenir;
bearer'a bağlı değil).

## Test
`tests/test_twitter_client.py` RSS'e göre yeniden yazıldı (bearer fixture kalktı):
başarı, html-unescape, baştaki-boşluk, id set, tüm-instance-düşer (`err`),
çoklu-instance fallback, 429 retry, backoff cap, `_clean_query` sıyırma +
URL'de operatör yok, instance yapılandırma. **12 twitter testi + toplam 215 test
yeşil.** `stocks.json` md5 baştan sona değişmedi (`b3294f6…`) — veri korundu.

## Canlı instance probe (2026-08-13) — KRİTİK BULGU
Uygulama yeni kodla çalıştırıldı; log gerçek instance sıralamasını doğruladı.
**Şu an hiçbir public Nitter instance'ı anonim RSS vermiyor:**

| Instance | Durum |
|---|---|
| nitter.net | 403 / boş |
| nitter.privacydev.net | Connection refused (kapalı) |
| nitter.poast.org | 403 (JS bot-challenge / Anubis) |
| xcancel.com → rss.xcancel.com | 200 XML **ama** e-posta whitelist gerektiriyor + bozuk XML (kaçırılmamış `&`) |
| nitter.tiekoetter.com | 200 **ama** Anubis "not a bot" challenge sayfası, 0 item |

**Sonuç:** Köprü kodu kusursuz çalışıyor (instance sırasını doğru dolaşıyor, 402
tamamen gitti), ama X/Cloudflare tüm açık instance'ları kapatmış → **bugün veri
getiremiyor.** Bu, planda "risk" olarak işaretlenmişti; canlıda doğrulandı.

**İleri yol (güvenilir ücretsiz):** kendi Nitter instance'ını (Docker + guest
token) çalıştırmak; sonra `NITTER_INSTANCES`'a ekle:
`security add-generic-password -U -s ekranhisse -a NITTER_INSTANCES -w 'https://...'`
veya `~/.ekranhisse/notes_config.env`'e `NITTER_INSTANCES=...`, ardından restart.
